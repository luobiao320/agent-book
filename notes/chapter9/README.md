## 1. 语音 Agent：级联、Omni 与全双工

## 核心结论
语音 Agent 不只是“加一个 TTS”。系统架构决定了延迟、可打断性和表达自然度。常见路线包括级联流水线、端到端 Omni 模型和全双工交互。

## 级联
ASR → 文本模型 → TTS。模块成熟、可替换、易调试，但串联延迟和信息损失较明显。

## Omni
单模型直接理解和生成多模态信号，能保留语气、停顿等信息，减少中间转换。

## 全双工
模型可以一边听一边说，支持打断、抢话和实时反馈，更接近自然人类交流，但状态管理和并发时序更复杂。

## 工程判断
先明确业务对延迟、成本、可控性和自然度的要求，再选择范式。

## 2. 实时交互中的快思考与慢思考

## 核心矛盾
用户希望语音系统立即回应，但高质量推理可能需要更长时间。实时 Agent 必须在“快速反馈”和“深度思考”之间调度。

## 常见策略
快模型先给确认、澄清或短反馈；慢模型在后台完成复杂推理，再给正式答案。也可以把表达层与深度规划层拆开。

## 交互原则
低延迟反馈不应制造虚假确定性。系统可以说“我正在查询”，但关键事实要等工具或深度推理返回后再确认。

## 工程重点
需要取消、打断、过期结果丢弃和会话状态同步。否则用户已改变话题，旧的慢任务仍可能突然把答案插进当前对话。

## 3. Computer Use：把 GUI 变成 Agent 的环境

## 核心结论
Computer Use Agent 通过截图、DOM/无障碍树等观察界面，再输出点击、输入、滚动、快捷键等动作。它把没有 API 的软件也纳入 Agent 的动作空间。

## 动作空间
动作应尽量语义清晰且有限，例如 click(x,y)、type(text)、scroll(direction)。开放脚本能力更强，但安全风险也更高。

## 闭环
观察屏幕 → 定位目标 → 执行动作 → 重新观察。任何一步都可能因页面变化而失效，因此不能依赖一次规划执行到底。

## 可靠性
重要操作应在动作后验证页面状态，避免“点了但没生效”“弹窗遮挡”等 GUI 特有问题。

## 4. 视觉 Grounding 与世界模型

## Grounding
模型需要把“点击登录按钮”这样的语义目标映射到屏幕上的具体位置或 DOM 元素。识别正确但定位错误，行动仍会失败。

## 动态世界
GUI 不是静态图片：动画、加载、滚动和弹窗会改变状态。Agent 需要判断动作如何影响下一帧，这实际上要求某种世界模型。

## 多模态观察
截图提供视觉信息；DOM/可访问性树提供结构；声音和动画又携带额外状态。不同观察通道可以互补。

## 工程原则
对关键动作优先使用稳定结构化定位；视觉坐标适合作为通用兜底。每次操作后重新观察，而不是假设环境按预期变化。

## 5. 机器人控制与 VLA

## 核心结论
机器人 Agent 把动作空间扩展到物理世界。高层 LLM 适合任务分解和长程规划，底层控制模型负责连续、实时的机械动作。

## 分层控制
高层：理解“整理桌面”并拆成找物体、抓取、移动、放置。
低层：根据视觉和机器人状态输出关节或末端执行器动作。

## VLA
Vision-Language-Action 模型直接从视觉和语言生成动作，把感知、语言理解和控制连接起来。

## 局限
物理世界容错低、反馈延迟和传感噪声复杂。高层规划再强，也需要底层安全控制、碰撞检测和动作约束。

## 6. 从仿真到真实世界

## 核心结论
真实机器人数据昂贵且危险，因此大量训练和评估会在仿真中进行。但仿真与现实存在 domain gap，策略在模拟器成功不代表真实可用。

## 缩小差距
随机化光照、材质、相机、物体位置和动力学参数，让策略不要过拟合单一模拟环境；再用少量真实数据校准。

## 世界模型
模型若能预测“执行这个动作后环境会怎样”，可以在行动前做内部模拟，减少盲目试错。

## 安全
真实部署必须有独立于模型的速度、力、工作空间和急停限制。对于物理 Agent，Harness 最终会延伸成控制系统的一部分。

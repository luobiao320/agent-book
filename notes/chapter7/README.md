## 1. 预训练、SFT 与 RL 的三阶段视角

## 核心结论
预训练、SFT 和 RL 不是三种互斥模型，而是不同训练阶段。预训练学习广泛语言与世界知识；SFT 用高质量示范塑造期望行为；RL 根据奖励让模型在任务环境中探索并强化策略。

## SFT 与预训练
二者都可以理解为“预测下一个 token”，区别主要在训练数据分布：SFT 使用更针对任务的输入—输出或完整轨迹。

## RL 的不同
RL 不要求给出唯一标准答案，而是通过 rollout 的结果奖励比较哪些行为更好，因此特别适合多条路径都可能成功的 Agent 任务。

## 选择
如果模型连基本格式和动作空间都没学会，先 SFT；如果会做但策略质量不稳定，需要从结果中优化决策，RL 更有价值。

## 2. SFT 数据：从示范到可训练轨迹

## 核心结论
Agent 的 SFT 数据不只是最终答案，而可以包含完整多轮轨迹：观察、思考/决策、工具调用、工具结果和最终响应。

## 数据来源
人工专家示范、强模型生成、成功线上轨迹、规则或程序合成。无论来源如何，都需要过滤低质量、矛盾和越权行为。

## 数据合成
可以先生成任务，再让 Teacher Agent 执行并验证，保留成功且高质量的轨迹。关键不是数量最大，而是覆盖希望模型学会的策略边界。

## 风险
如果把 Harness 的偶然 bug、过时工具格式或投机路径写进训练数据，模型会把这些行为固化。数据必须和当前环境契约一致。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter7/

## 3. RL：Rollout、优势与参数更新

## 核心结论
RL 训练常对同一个任务采样多条 rollout，让模型尝试不同策略；环境对结果评分，再用这些反馈更新参数，使高回报动作更可能出现。

## 为什么需要多次 rollout
单次结果无法区分“策略好”与“碰巧成功”。多个样本提供相对比较，让算法估计哪些决策更值得强化。

## Agent 场景
一条 rollout 可能包含多轮工具交互，成本明显高于单轮问答。训练效率取决于环境速度、并发、轨迹长度和奖励质量。

## 关键认识
RL 算法名字不是全部，真正决定 Agent RL 成败的往往是任务分布、环境可验证性和奖励设计。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter7/

## 4. RL 环境：从评估场到训练场

## 核心结论
好的 RL 环境与好的评估环境高度相关：都需要初始化状态、工具、反馈和客观判定。但训练环境允许模型反复试错，因此还要强调吞吐、隔离和防投机。

## 真实环境难构建怎么办
可以用模拟器或模型扮演用户/环境，但模拟误差会成为训练信号的一部分。越关键的能力，越应使用可验证的真实或高保真环境。

## 隔离
训练任务分布、开发回归集和最终测试集必须分开，否则模型可能只记住题目而非学会泛化策略。

## 工程视角
环境是 RL 的“产品需求文档 + 测试平台 + 奖励接口”三者合一。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter7/

## 5. 奖励设计：结果、过程与路径约束

## 核心结论
奖励把“我们想要什么”转成训练信号。最简单的是最终成功/失败，但复杂 Agent 还可能需要过程反馈、安全约束和多目标奖励。

## 奖励来源
确定性规则适合可验证任务；人类偏好适合主观质量；模型评判适合规模化但需校准。

## 结果 vs 过程
只看结果可能鼓励投机路径；只奖励过程又可能限制模型找到新策略。实践中可把硬约束与最终目标结合。

## 路径约束
即使结果正确，也可能通过危险、违规或不可维护的方法完成。对生产 Agent 来说，“怎么完成”有时和“是否完成”同等重要。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter7/

## 6. 蒸馏与样本效率

## 核心结论
蒸馏的目标是把更强策略产生的信息转换成更密集、更便宜的监督，让较小或当前模型更快学习。

## On-Policy Distillation
学生先按自己的策略 rollout，再由教师对学生真实遇到的状态提供指导。相比只学习教师离线轨迹，这更贴近学生当前的错误分布。

## 自蒸馏
没有更强教师时，也可以让同一模型通过更多推理、搜索或多样本选择产生高质量目标，再训练较轻量的策略。

## 风险
教师不是绝对正确。蒸馏前应通过环境验证或 Judge 过滤，避免把教师幻觉高效复制给学生。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter7/

## 7. 从线上 Bad Case 到后训练

## 核心结论
后训练不应从“想训练什么能力”凭空开始，而应从可重复的失败模式出发：收集 bad case → 归因 → 构造任务分布 → 建环境与奖励 → 训练 → 回归验证。

## 先问是否需要训练
很多问题可以先通过工具改造、Prompt、Skill 或 Harness 修复。只有当问题属于模型内在策略且在大量场景中重复出现时，参数更新才值得投入。

## 防止局部修复
针对一个 bad case 训练可能破坏其他能力，因此要同时跑通用回归、安全集和未见分布。

## 实践原则
把训练看成 Agent 工程的最后一层优化，而不是遇到任何失败就“微调一下”。

## 1. 从运行轨迹提取可靠学习信号

## 核心结论
保存轨迹不等于学习。真正的学习需要对经验进行**评价、对照、归纳、验证**，从中提取可泛化的策略，而不是把所有历史原样塞回上下文。

## 信号来源
评估结果、用户反馈、工具错误、人工审核、A/B 实验和回归测试都可以提供学习信号，但每类信号都有偏差。

## 关键步骤
先判断任务是否真的成功，再定位关键决策，比较成功与失败轨迹，提取候选经验，最后在独立任务上验证。

## 风险
未经验证的用户反馈、提示注入或偶然成功如果直接写入长期能力，会把错误放大到未来所有任务。

## 2. 持续进化的四种落点

## 核心结论
经验可以沉淀到四类产物：**知识、指令、程序、模型参数**。它们对应不同成本和表达能力。

## 四种方法
- 知识：更新文档、记忆或知识库，适合事实。
- 指令：更新 Prompt/Skill，适合可语言化策略。
- 程序：更新 Harness、校验器、工作流，适合确定规则。
- 参数：后训练模型，适合难以显式表达、需要泛化的能力。

## 选择原则
能用低成本、可审计方式解决的，不必立刻训练模型。越往参数层走，更新成本越高、回滚越困难，但表达能力也越强。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter8/

## 3. 可长期运行的进化闭环

## 核心结论
持续进化需要一条受控流水线，而不是生产 Agent 自己随时修改自己。

## 闭环
线上轨迹 → 自动/人工评估 → 失败聚类与归因 → 生成候选改进 → 离线验证 → 灰度发布 → 在线监控 → 必要时回滚。

## 为什么要独立验证
新规则可能修复一类失败，却伤害其他任务。所有候选更新必须经过回归集和安全集，避免局部最优。

## 元学习
系统还可以优化“如何产生更新”的方法，例如更好的 bad case 聚类器、Prompt 优化器或 Skill 生成器，但这些元方法本身同样需要版本化和评估。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter8/

## 4. 验证、发布、回滚与安全边界

## 核心结论
Agent 能自我改进并不意味着它应拥有无限自修改权限。生产系统必须把“提出改动”和“批准改动”分开。

## 发布机制
候选改动使用独立分支/版本；通过自动评估后再灰度；监控关键指标；出现退化可以快速回滚到上一个已知稳定版本。

## 安全边界
- 不从单条用户指令直接学习全局规则。
- 不允许经验自动扩大权限。
- 安全约束和核心合规策略需要更高审批等级。
- 所有自动修改都应可追踪来源和证据。

## 原则
持续进化首先是一套治理系统，其次才是“让 Agent 越来越聪明”的算法。

## 5. 睡眠学习：整理、遗忘与能力保鲜

## 核心结论
长期运行系统需要类似“睡眠”的离线整理阶段：合并重复经验、删除过期信息、重跑评估、更新索引和生成候选能力改进。

## 为什么需要遗忘
知识和工具会变化。永久保留所有经验会让旧规则与新规则冲突，增加检索噪声。遗忘应基于版本、时间和验证结果，而不是简单按年龄删除。

## 能力保鲜
周期性跑核心回归集，发现某个 Skill、工具或模型升级是否导致旧能力退化。

## 工程类比
类似数据库 compaction + 搜索索引重建 + CI 回归测试的组合：在线阶段专注执行，离线阶段专注整理和优化。

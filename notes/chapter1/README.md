## 1. Agent = LLM + 上下文 + 工具

## 核心结论
现代 Agent 可以先用一个工程公式理解：**Agent = LLM + 上下文 + 工具**。LLM 负责决策；上下文决定模型此刻“看见什么”；工具把决策转成对外部世界的读取或行动。Environment（网页、文件、数据库、用户、物理世界）不是 Agent 本体，而是 Agent 通过接口交互的外部环境。

## 为什么重要
很多 Agent 问题并不是“模型不够聪明”，而是上下文缺少关键信息，或工具没有提供完成任务所需的动作。排查时应分别问：模型是否会做？模型是否看得到？模型是否做得到？

## 工程视角
可以把 Harness 看成包围模型的运行层：负责构造上下文、暴露工具、维护循环、做权限控制和结果校验。模型能力越强，Harness 越需要把自由度转化为可控执行。

## 自测
如果模型知道如何删除一个云文件，但系统没有提供删除工具，它为什么仍然不能完成任务？

## 2. 观察空间与动作空间

## 核心结论
Agent 与环境之间通过“观察”和“动作”形成闭环。观察空间决定 Agent 能获取哪些信息；动作空间决定 Agent 能做哪些事情。上下文是观察在 Agent 内部的表示，工具则定义可用的观察/动作接口。

## 关键直觉
提升 Agent 能力不只有升级模型这一条路。把缺失的数据接入上下文，或把必要操作封装成工具，往往就能让原本不可解的任务变得可解。

## 工程检查表
1. 任务所需信息是否能被读取？
2. 读取结果是否以模型容易理解的格式进入上下文？
3. 任务所需动作是否有对应工具？
4. 高风险动作是否被限制在最小权限范围？

## 自测
一个 Agent 能“看懂”网页截图，却没有点击工具；另一个 Agent 能点击 DOM 元素，却拿不到页面内容。两者分别缺了什么？

## 3. ReAct 循环：思考—行动—观察

## 核心结论
Agent 的基本运行方式不是一次性生成最终答案，而是循环执行：**理解当前状态 → 选择下一步行动 → 调用工具 → 读取结果 → 再决策**。这类思考与行动交替的结构通常可用 ReAct 来理解。

## 最小循环
用户请求进入上下文后，模型可以直接回答，也可以产生工具调用；Harness 执行工具并把结果追加到上下文；模型基于新观察继续执行，直到满足终止条件。

## 容易出错的地方
- 工具结果没有回填：Agent 会重复调用。
- 历史被错误删除：Agent 会忘记已经做过什么。
- 没有终止规则：可能陷入无限循环。
- 只让模型“规划”却不验证行动结果：计划与环境状态会逐渐偏离。

## 工程原则
每一步都应形成可观察轨迹：输入、模型决策、工具调用、工具结果、最终状态。

## 4. Harness 工程

## 核心结论
生产级 Agent 的竞争力不仅来自模型，还来自模型外围的 Harness。Harness 的职责包括上下文管理、工具接口、状态维护、验证纠错、安全边界与执行治理。

## 为什么不能只靠 Prompt
Prompt 能影响模型行为，但无法可靠承担权限隔离、事务一致性、幂等、超时、重试、审计等系统职责。这些约束应由程序化 Harness 承担。

## 典型分层
- Model：理解、规划、选择行动。
- Context layer：组织系统指令、历史、状态、检索内容。
- Tool layer：对外部能力做受控封装。
- Runtime：循环、超时、重试、并发、持久化。
- Guardrail：权限、校验、人工确认、回滚。

## Java 类比
可以把模型视为一个“非确定性策略服务”，Harness 类似你熟悉的服务治理层：不能因为业务逻辑聪明，就取消鉴权、熔断和事务控制。

## 5. 工作流与自主 Agent 的编排选择

## 核心结论
Agent 编排大致可分为两端：确定性工作流和自主决策。工作流由程序预先规定步骤，自主 Agent 由模型根据状态动态选择下一步。实际系统常是两者混合。

## 什么时候用工作流
步骤稳定、规则明确、错误代价高、需要强可审计性时，用程序控制主流程更合适。

## 什么时候用自主 Agent
任务开放、路径未知、需要搜索探索、不同输入可能需要完全不同策略时，让模型拥有更大决策空间更有价值。

## 混合范式
把不可变的业务约束做成工作流，把路径选择和信息探索交给 Agent。例如“退款必须经过资格校验和人工确认”可以固定，而“如何收集证据”可由 Agent 自主决定。

## 判断标准
不是“Agent 越自主越高级”，而是：给模型的自由度是否真的带来收益，且能否被验证与兜底。

## 6. 模型选择、护栏与人工干预

## 核心结论
模型选型和安全设计必须放在真实 Agent 任务中评估。更强模型未必总是更优：延迟、成本、工具调用稳定性、长上下文能力和特定任务行为都很重要。

## 护栏的层次
输入侧可做内容与权限检查；行动侧限制工具范围和参数；结果侧做格式、事实或业务规则验证；高风险节点加入人工确认。

## 人工干预
Human-in-the-loop 不是 Agent 失败后的补丁，而可以是设计的一部分。对于支付、删除、发布、医疗或法律等高风险动作，模型可以负责准备方案，人类负责最终授权。

## 工程原则
让“模型负责判断”与“系统负责约束”分工明确。安全规则如果能用确定性代码表达，就不要只依赖自然语言提示。

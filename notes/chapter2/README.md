## 1. 从 API 理解上下文

## 核心结论
上下文工程研究的是：每次调用模型时，究竟让它看到哪些信息、以什么顺序和结构看到。常见上下文包含 system、user、assistant、tool 等角色消息，以及工具定义。

## 四种角色的作用
- system：身份、规则、长期稳定约束。
- user：用户请求与补充信息。
- assistant：模型之前的回复、工具调用等轨迹。
- tool：外部工具执行结果。

## Agent 循环
一次工具调用并不是 API 的终点。模型先返回工具请求，Harness 执行后把 tool result 追加回消息历史，再次调用模型，直到得到最终答案。

## 工程原则
不要把上下文当成“聊天记录字符串”。它是 Agent 的运行时状态载体，消息角色、顺序、完整性都会影响行为。

## 2. 系统提示词的工程化设计

## 核心结论
好的系统提示词应同时处理人格/语气、结构、流程和业务规则。相比不断堆“禁止做 X”的散乱规则，更稳定的方法是给模型明确的工作流程、决策边界和输出格式。

## 设计方法
1. 先写任务目标和身份。
2. 再写必须遵循的流程。
3. 对高风险规则给出清晰的条件—动作关系。
4. 用结构化标题降低规则之间的冲突。
5. 只有当模式难以语言描述时，再加入 few-shot 示例。

## Few-shot 的价值
示例适合教“风格、格式、隐含判断模式”，但会占上下文并增加维护成本。能用明确规则说明的，不必靠大量示例。

## 自测
如果模型经常漏掉某一步，优先加一句“必须做 X”，还是重构成显式流程？为什么？

## 3. 动态提示词与 Agent Skills

## 核心结论
当系统能力越来越多时，不应把所有领域规则和操作说明永久塞进 system prompt。Skill 可以把一组面向任务的知识、流程和工具使用说明封装成可按需加载的能力单元。

## 为什么需要渐进式披露
所有内容全量注入会造成上下文膨胀、注意力稀释和缓存破坏。更好的方式是先暴露 Skill 的简要目录，确定需要某项能力后再加载详细说明。

## Skill 与工具
工具解决“能调用什么接口”；Skill 更像“如何完成某类任务”。Skill 可以指导模型组合多个工具，也可以包含领域规则、示例和工作流。

## 工程价值
把稳定核心 Prompt 保持精简，把长尾能力拆成独立 Skill，有利于版本管理、权限控制、测试和复用。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter2/

## 4. Agent 状态栏与轨迹管理

## 核心结论
长任务中，完整历史并不等于清晰状态。Agent 状态栏的目标是把当前任务的关键元信息显式化，例如目标、阶段、已完成项、待办、约束和风险。

## 为什么有用
随着轨迹增长，重要状态可能被埋在几十轮消息里。状态栏相当于一份持续更新的“工作台摘要”，降低模型重新从历史中推断状态的成本。

## 典型字段
- 当前目标
- 已完成步骤
- 下一步计划
- 已知约束
- 关键中间结果
- 待用户确认事项

## 缓存代价
如果状态栏位于上下文前部且每轮原地修改，可能破坏前缀缓存。工程上要在“状态可见性”和“缓存友好”之间权衡，可考虑将动态状态放到靠后位置或使用可编辑 KV 等高级能力。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter2/

## 5. 上下文压缩与分层管理

## 核心结论
上下文过长的问题不只是超出窗口，还会造成成本上升、推理延迟增加和有效信息被噪声淹没。压缩的目标是保留未来决策真正需要的信息。

## 常见策略
- 删除可重新获取的低价值工具输出。
- 把旧轨迹总结成阶段性摘要。
- 将大文件留在外部存储，只在需要时检索片段。
- 为不同信息设置保留等级：原文、摘要、索引、丢弃。

## 分层思路
热信息直接放上下文；温信息保留摘要或索引；冷信息放文件系统/知识库，需要时再取回。

## 重要认识
压缩不是越激进越好。丢掉决策依据、错误记录或约束，会使 Agent 重复犯错。压缩策略必须围绕“未来是否还需要”来判断。

> 来源章节：https://bojieli.github.io/ai-agent-book/book/chapter2/

## 6. 提示注入与上下文安全

## 核心结论
Agent 会把网页、邮件、文件、工具结果等不可信内容放进上下文，这些内容可能包含试图改变模型行为的指令。提示注入的本质是：数据与指令共享同一自然语言通道。

## 防护原则
- 明确区分可信系统指令和不可信外部数据。
- 高风险行动依赖程序化权限，而不是模型“自觉”。
- 工具调用采用最小权限。
- 外部内容不能自行扩大工具权限。
- 对关键动作做参数校验、预览或人工确认。

## 关键认识
Prompt Injection 很难只靠“再加一条 Prompt”彻底解决，因为攻击内容与正常内容都由模型解释。真正可靠的防线来自 Harness 中的权限、隔离和验证。

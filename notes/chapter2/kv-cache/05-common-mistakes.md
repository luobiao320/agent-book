# 05｜破坏缓存命中的常见错误

## 错误 1：把高频变化信息放在最前面

例如：

```text
当前时间：2026-09-10 00:43:12
请求 ID：abc123
你是一个智能 Agent……
```

如果时间或请求 ID 每次都变化，那么整个前缀从开头就不同，后面即使有大量固定内容，也很难复用。

更好的做法：

```text
你是一个智能 Agent……
[固定规则]
[固定工具说明]

动态信息：
当前时间：...
请求 ID：...
```

## 错误 2：每轮都重写 System Prompt

有些 Agent 框架会根据状态动态拼接 System Prompt。

例如：

```text
你当前已经执行了 3 个工具……
```

下一轮变成：

```text
你当前已经执行了 4 个工具……
```

如果这个状态位于 System Prompt 前部，就会导致稳定前缀被破坏。

更推荐：

- System Prompt 尽量保持静态；
- 动态状态作为后续消息追加；
- 不要为了表达当前状态而反复重写历史内容。

## 错误 3：工具定义顺序不稳定

假设有三个工具：

```text
search
calculator
weather
```

下一次请求却变成：

```text
weather
search
calculator
```

虽然工具内容没有变化，但序列发生变化，同样会影响前缀复用。

因此最好：

- 工具顺序固定；
- JSON 字段顺序尽量稳定；
- 描述文本不要无意义变化。

## 错误 4：删除再重建历史，而不是追加

Agent 运行过程中，经常需要记录新的观察结果。

不推荐：

```text
重新生成一份完整上下文
```

更推荐：

```text
已有稳定历史
    +
新的 tool result
    +
新的 assistant message
```

也就是尽量采用 append-only 思路。

## 错误 5：在 Prompt 里注入随机值

例如：

- UUID
- 随机数
- trace id
- 纳秒级时间戳
- 每次变化的调试信息

这些数据如果必须给模型看，尽量靠后放；如果模型根本不需要知道，就不要放进 Prompt。

## 一个判断原则

对于每一段上下文，都问两个问题：

1. 这段内容多久变化一次？
2. 它是否必须出现在稳定内容之前？

如果答案是“变化很频繁”且“不必须放前面”，就应该把它后移。

# 01｜KV Cache 的核心直觉

## 先抓住一句话

**KV Cache 的本质，是避免模型在生成每一个新 token 时，重复计算已经看过的历史 token。**

大模型通常采用自回归生成方式：一次只生成一个 token。

假设输入是：

```text
用户：请解释一下 KV Cache
```

模型生成第一个 token 后，为了继续生成第二个 token，它还需要重新参考前面的整段上下文；生成第三个 token 时，又要再次参考更长的上下文。

如果每一步都从头计算，很多计算其实是在重复做。

KV Cache 就是在这里发挥作用：

- 历史 token 的中间结果已经计算过；
- 把这些结果缓存起来；
- 下一步生成时直接复用；
- 只为最新 token 计算新的部分。

## 一个类比

可以把它理解成做数学题时的“草稿纸”。

如果前 10 步已经算完，第 11 步应该基于已有结果继续，而不是每次都从第 1 步重新计算。

KV Cache 保存的，就是 Attention 计算过程中可以被复用的历史信息。

## 为什么它对 Agent 特别重要

普通聊天可能只有几轮对话，但 Agent 往往会不断追加：

- System Prompt
- 用户任务
- 工具定义
- 历史消息
- 工具调用结果
- 中间推理结果
- 新一轮观察结果

上下文会越来越长。

如果这些前缀保持稳定，缓存就能持续复用；如果每一轮都修改前面的内容，就会导致大量缓存失效。

## 记住这个工程结论

设计 Agent 上下文时，不只要考虑“模型能不能理解”，还要考虑：

> **哪些内容应该稳定放在前面，哪些内容应该只追加到后面。**

这会直接影响延迟、吞吐和推理成本。

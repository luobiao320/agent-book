# 上下文：决定 Agent 能力上限的关键

原文：https://bojieli.github.io/ai-agent-book/book/chapter2/#上下文决定-agent-能力上限的关键

## 核心结论

Agent 的能力不只由模型参数决定，更受它在每个决策点能获得的上下文质量限制。代码信息、流程规范、环境信息等背景知识如果缺失，再强的模型也可能做出脱离实际项目的决策。

上下文工程因此不是“往 prompt 里塞更多文字”，而是系统地设计信息的来源、结构、顺序和更新方式，让模型在需要时看到足够而准确的信息。

## 工程理解

- 对 Agent 友好的团队通常也是文档化、可检索、流程透明的团队。
- API 本身是无状态的，每轮都要由 Harness 重建本轮需要的上下文。
- 后续的 KV Cache、状态栏、Skills、压缩，本质都在解决同一个问题：如何用更低成本提供信息充分的上下文。
